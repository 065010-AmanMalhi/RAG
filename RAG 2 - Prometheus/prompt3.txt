Alright I have a task at hand. Design and implement an Agentic Retrieval-Augmented Generation (RAG) system consisting of two sub-systems built using LangChain and LangGraph, running inside Docker on Ubuntu, with PostgreSQL (pgvector extension) used as the vector database. Ollama is installed within Docker.

Sub-System 1 – Agentic RAG Pipeline
Build an agentic RAG pipeline that deploys:

A small language model: <small_llm>, Model size must be < 1GB, Context window: <context_size>
A lightweight embedding model: <embedding_model>

The system should perform retrieval-augmented generation over a dataset stored at <dataset_path>. The dataset will be provided in .txt format.
The vector store must be implemented using PostgreSQL with the pgvector extension.
Database configuration — Role: <role_name>, User: <user_name>, Database: <database_name>
Agentic Behaviors
The agent must exhibit the following autonomous behaviors via a LangGraph state machine:

Query Rewriting — rewrite ambiguous or underspecified queries before retrieval
Retrieval Retries — retry with a revised strategy if retrieved context scores below a relevance threshold
Multi-hop Decomposition — break complex questions into sub-queries and aggregate retrieved context
Fallback Handling — explicitly abstain or flag responses when retrieved context is insufficient rather than hallucinating

Question & Answer Inputs
The evaluation inputs are provided as two .txt files in numbered list format (e.g. 1. question):

Questions file: <questions_path>
Expected answers file: <answers_path>

Both files must contain the same number of entries and be processed index-wise.
Workflow

Load Question and Answer Files

Read the questions .txt from <questions_path>
Read the expected answers .txt from <answers_path>
Validate that both files contain the same number of rows


Sequential Pairing

Iterate through the files index-by-index
For each index i retrieve question_i and expected_answer_i


RAG Query Execution

For each question_i pass the question to the Agentic RAG pipeline
Retrieve relevant context from the PostgreSQL pgvector database
Generate an answer using <small_llm>


Response Packaging

For every processed question store: Question, Generated Answer, Expected Answer, Retrieved context snippets, <small_llm> and <embedding_model> names



Sub-System 2 – Evaluation System

Use llama3.2 as a judge LLM to evaluate the outputs generated by Sub-System 1 against the expected answers using <evaluation_framework>. Score each response on Answer Relevancy, Faithfulness and Contextual Precision.
Output Storage
All results must be written into a single JSON file: output_rag.json. Each entry must include: Question, Generated Answer, Expected Answer, Retrieved Context, Evaluation scores, Evaluation framework used, <small_llm> name and <embedding_model> name.
Notes

All model names and evaluation frameworks must be parameterized to support multi-instance runs
Model selections should follow the models.txt reference file
The RAG system must be fully reproducible across different <small_llm> × <embedding_model> combinations
Questions and answers are provided in separate .txt files in numbered list format and must be paired sequentially by index
All Ollama models are pre-loaded inside the Docker image and do not require runtime pulls
